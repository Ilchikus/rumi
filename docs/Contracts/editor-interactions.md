# Editor Interactions

The proven Rumi editor is the functional baseline for the official editor. Its ProseMirror schema,
commands, plugins, NodeViews, and interaction styling are migrated together so the editing model is
preserved. Browser/platform adapters replace its Electron and direct-filesystem calls; Markdown
remains the durable representation and workspace operations remain server-owned.

The repository-level [Markdown syntax reference](../../MARKDOWN.md) defines the GFM baseline,
Rumi-specific source extensions, and read-time compatibility rules used by this contract.

## Behavior Map

| User problem | Action | Expected result |
| --- | --- | --- |
| Configure writing assistance, startup, and uploads | Open Settings from the Gear action above Trash and change an editor, startup, or upload control | `/settings` is an editor-like system page with the same title, content container, and fixed-width address bar as an ordinary page. Settings are not divided into named sections: each setting is one name/compact-description/options row. File-format options alone use two checkbox columns and show lowercase dotted extensions. Native checkboxes use the Sky 600 accent. Valid changes save automatically without a Save button, and serialized persistence prevents an older request from replacing a newer change. Misspelling highlighting defaults off; inline replacements and emoji suggestions default on. The shadcn-style inline-toolbar dropdown offers `Floating`, `Top`, and `None`: Floating keeps the compact selection toolbar, Top keeps the expanded left-aligned toolbar fixed above the viewport's bottom safe-area inset and aligned to the editor column, and None hides it. All editor preferences update the live editor without remounting or losing undo history. The browser-local startup dropdown defaults to `Last visited`, can instead open `Home`, and is scoped to the current workspace and browser rather than shared through workspace configuration. Upload size defaults to 50 MB; blank means unlimited and zero disables uploads. Clearing every format checkbox also disables uploads. Changes apply to subsequent uploads. |
| Start or reopen a workspace | Open an authenticated Rumi instance at `/`, including after closing the prior browser session | The sidebar, header, and empty editor geometry render without loading-state copy. By default the last visited page and its last successfully loaded or saved content hydrate from a bounded browser-local startup snapshot, then reconcile to fresh server state. Choosing `Home` in Settings opens the workspace root instead. Explicit deep links always win. The last visited target survives sessions, but page scroll positions do not: a newly opened Rumi session starts its page at the top. Cached Markdown never renders before authentication and never replaces an unsaved draft. |
| Navigate with browser history or share an open item | Open a page, folder, database, record, or Trash; scroll it; navigate elsewhere and revisit it; use Back/Forward or load its URL directly | The address changes to a URL-safe workspace slug. Back/Forward restores that history entry's exact editor-canvas position, while ordinary in-app revisits restore the page's latest in-memory position during the current application session. Deep links survive refresh, and the persistent application layout does not remount. Scroll state is not written to persistent browser storage and is not restored after closing and reopening Rumi. |
| Move an open page to Trash | Choose Move to Trash from its menu | The reversible move happens immediately without confirmation, and Rumi opens the latest surviving page from the in-app visit history. |
| Review or remove a trashed page | Open Trash, select a viewable item, then Restore or Delete | Trashed pages remain addressable in a read-only page view even though they are absent from the sidebar. Restore is reversible; Delete always asks for confirmation that the operation is permanent and irreversible. |
| Rename or split the open-page title without leaving the editor | Click the filename text or the unused part of its row, edit it, then blur or press Enter | Text clicks preserve the exact caret position; row clicks place it at the end. Blur renames, while Enter keeps the title before the caret and moves the remainder into a new first content block. Mod-Z reverses either operation as one action, restores the original title, and reopens it with the caret at the end. The extension stays hidden, pending edits save first, and Escape cancels. |
| Create or rename a spaced workspace item from the sidebar | Type a page, folder, or database name containing ordinary spaces and submit it | The controlled input retains in-progress spaces. Portable unsafe characters are still replaced, while leading and trailing whitespace is trimmed only at submit. Sidebar and inline-title naming accept the same ordinary spaces. |
| Create structure without leaving the keyboard | Type Markdown prefixes or use `/` | Headings, lists, tasks, quotes, code, Mermaid, dividers, tables, bookmarks, database references, images, and files become semantic blocks. Typing `[]`, `[x]`, `- []`, `- [x]`, `-[]`, or `-[x]` at the start of a line and then pressing Space creates an unchecked or checked task item; the spaced GFM form `- [ ]` is accepted too. The bracket sequence remains literal until that trailing Space. The slash menu follows the active line through native editor scrolling, prefers the space below it, flips above when needed, and scrolls internally when neither side can fit it in full. |
| Enter symbols and emoji without leaving the keyboard | Type a supported ASCII combination, or type `:` at a prose boundary and continue with an emoji query | Inline combinations such as `->`, `<->`, `<=`, and `<=>` become `→`, `↔`, `≤`, and `⇔` in live ProseMirror state and later save as literal UTF-8 Markdown. Chained arrow matches remain one logical undo action. A valid `:smile` query opens Rumi's dependency-free, caret-anchored emoji selector with `😄` focused; Enter replaces the exact query, while Escape closes the selector and leaves it literal. Code, Mermaid, inline code, URLs, timestamps, paste, load, and programmatic changes do not trigger either feature. |
| Continue naturally around special blocks | Press Enter, Backspace/Delete, Shift-Enter, Tab, Shift-Tab, an arrow key, or Mod-Enter | Lists split without discarding an empty current item: Enter preserves that bullet, number, or task row and creates another row of the same kind. Backspace or Delete on an empty formatted text block, including a heading or list item, resets it to a plain blank paragraph while preserving the caret on the same line. On an already-plain blank paragraph, the same key removes that paragraph and moves the caret to the previous text block's end. Mermaid source is ordinary ProseMirror code content, so it accepts a normal text caret, literal paste, tabs, Shift-Enter newlines, and the editor's single undo history. Database embeds and dividers each expose leading and trailing structural caret positions on their own row: the database's leading caret appears at its top-left corner and its trailing caret at its bottom-right corner. Arrow navigation crosses between those positions without highlighting the whole block, and Delete from the leading or trailing position removes that block. Removing a trailing blank paragraph leaves the matching trailing caret; a file embed remains the sole caretless inactive boundary. Mod-Enter adds a paragraph after the current block and Shift-Mod-Enter adds before; inside code or Mermaid, Mod-Enter retains the code-exit behavior. One LF is a stable visible soft break within a paragraph, a blank line is the paragraph/block boundary, and explicit hard breaks remain compact and inline. Tables move between cells. |
| Paste from plain, rich, and Rumi sources | Use normal paste or the platform paste-as-plain-text shortcut | Normal paste prefers an exact Rumi structural flavor, then supported semantic HTML, then text. An explicit block selection is the paste replacement range even when ProseMirror's native selection is only a stale cursor or one selected node: every selected block is removed, pasted content starts at the first selected block, and both block and native node highlights clear to an available text cursor afterward. Google Sheets ranges become table blocks through rich HTML. Semantic lists from Google Docs and similar editors become flat Rumi list blocks with their available family and nesting; block wrappers inside rich table cells are flattened into inline cell content without breaking the table. A Google Docs paragraph run becomes code only when every line retains both the portable code font and background; ordinary monospace prose remains prose. Docs' default visual link underline remains presentation rather than becoming an explicit Rumi underline mark, and whitespace Docs folds into the anchor boundary returns outside the link when it separates surrounding text instead of becoming part of the link label. When an intermediary strips private metadata but leaves an unambiguous Mermaid grammar or database configuration run, Rumi promotes that text back to its semantic block; metadata absent from both returned HTML and text cannot be recovered. Paste-as-plain-text ignores HTML and treats Markdown punctuation literally, while preserving single LFs as soft breaks and blank lines as paragraph boundaries; code paste remains literal. |
| Connect knowledge quickly | Type `@`, paste a URL over selected text, press Mod-Shift-K, edit a link, or deliberately follow one | A Markdown link is inserted. Mod-K remains the application-wide search shortcut; adding Shift opens the same link action as the editor toolbar without colliding with search. Internal destinations are URI-decoded and resolved from the containing document or workspace root, then the matched node receives its current application slug; application slugs are never written over canonical file paths. A plain primary click places the caret in linked text without navigating; Command-click opens it in a new tab. External links end with a regular Phosphor ArrowSquareOut icon: clicking the icon opens the current tab and Command-clicking it opens a new tab. Link text keeps a text cursor and changes hover color only while Command is held, while the icon always uses a pointer cursor and changes color on hover. Secondary-click selection is suppressed without handling the context-menu event, so the browser's native Open/Copy Link menu remains available. Link text and destination can also be copied, edited, or removed through Rumi's hover controls. |
| Format selected text | Triple-click a row, press Mod-A, use the selection toolbar, or use formatting shortcuts | Triple-click selects only the clicked hard-break-separated row, including inside code blocks. It never expands that row to the whole multi-row block. The first Mod-A selects the cursor's whole block without opening its context menu, so typing can replace that block; a second Mod-A selects every block. Bold, italic, underline, strike, code, the single default yellow highlight, and links are applied as Markdown-backed marks. When blocks are explicitly selected, toolbar actions and formatting shortcuts apply to every selected block, including non-contiguous selections, without formatting unselected blocks between them. A mixed selection becomes uniformly marked on the first toggle and uniformly unmarked on the next. Toggling the checkbox of a selected task gives every selected task the toggled checked state; selected non-task blocks are unchanged. The Top toolbar separates block placement, undo/redo, block conversion/media, inline formatting, and final block deletion into five groups divided by vertical borders. The groups distribute across the bar's full available width while controls inside each group remain compact. Its block conversions share the handle context menu's transaction behavior but omit Mermaid, Table, and Divider, which remain available from the handle menu. Placement, movement, history, and replacement controls show their shortcuts in the button title. Toolbar and hotkey undo/redo invoke the same ProseMirror history commands. Inline actions preserve and format the highlighted text, while delete invokes the same canonical whole-block deletion as the handle menu. Floating retains only the existing compact inline controls. |
| Reorganize document structure | Use each block's handle, Command-D, modifiers, area selection, or drag | Command-D duplicates the explicit block selection, or the cursor's whole active block when there is no block selection; the duplicate becomes the active block selection. One or many blocks can also be deleted, reordered, and, for list items, indented or outdented. Shift-Up/Down retains native ProseMirror behavior for inline selections; for explicit block selections it adds the adjacent block in that direction. Shift-Mod-Up/Down likewise retains native inline behavior but extends a block selection to the matching document edge. A held marquee remains attached to its original document point while the page scrolls, continues extending over newly revealed blocks, and proportionally auto-scrolls inside the top and bottom 100-pixel viewport zones. Every block-delete entry point removes the selected block nodes completely and normally maps focus to a surviving block; deleting the entire document leaves the schema's required empty paragraph. When deletion exposes a following Mermaid block, its real code caret moves to the source start. When it exposes a database embed or divider, the leading structural caret becomes active without a whole-block highlight. A selected blank paragraph after Mermaid returns to Mermaid's source end; after a database embed or divider it leaves the trailing structural caret. A top-level list drop crosses into its first indent after 30% of the editor width; a drop beneath an already-indented item aligns with that item until it crosses 20% of the target item's own width, then nests one level deeper. Every list item is independently addressable. Any click outside the editable block area clears both its block highlight and NodeSelection after the clicked control completes its own behavior. |
| Change a thought's role | Press Mod-/, right-click a block handle, or select one or more blocks and type a type name after explicitly opening the menu | Mod-/ toggles the same menu as right-clicking a block handle. It uses an existing block selection or selects the cursor's current block when needed, without expanding that selection; pressing Mod-/ again closes the menu. Selecting blocks through handles, Mod-A, or area selection remains quiet and does not open the menu. Right-clicking a selected block's handle preserves the complete selection; activating a handle outside the selection first resets selection to only that block so stale blocks cannot receive the action. The selection-opened menu remains outside the content column with an 8-pixel gap before the content start. The first printable key reaches search even during the handle's drag-safe focus handoff, so it never replaces the selected block. Typing filters and focuses the first match so Enter applies it. Backspace on the initially empty search still deletes the selected blocks, while Backspace edits the query after typing begins. The selected blocks convert among text, heading levels, bullet/number/task lists, quote, code, and divider while preserving useful text. Converting one multiline paragraph to a bullet, numbered, or task list creates one list item per visible line and retains each line's inline marks. Converting a single-column table creates one list item per row and retains in-cell marks and line breaks. Conversion then clears block selection and places the cursor at the end of the last converted block. |
| Focus on one section | Toggle a heading caret, press Enter at the end of a collapsed heading, or click below a final collapsed section | Expanded headings reveal the caret only over the caret's own hit target; collapsed headings keep it visible. Blocks and their external hover controls until the next equal-or-higher heading or divider hide or reappear immediately, without a layout transition or residual rich-block box. Enter at a collapsed heading's end keeps its existing section hidden, inserts or reuses a divider after that section, and focuses a visible blank paragraph below the divider, including when selection remained inside a newly hidden code block. Clicking below the document uses the same exit when the final visible block is a collapsed heading even though hidden descendants are the stored final nodes. Otherwise that click focuses an existing final blank paragraph or appends and focuses a normal paragraph without a divider. Expanded-heading Enter retains normal split behavior. The divider persists as `---` and is excluded from collapsed-section visibility and drag/drop ranges; collapse state itself remains presentation-only. |
| Work with tables | Put the cursor in a table or scroll the document around it | Table row/column controls are hidden while their interaction is redesigned. Tab and Shift-Tab still navigate cells and column resizing remains available. A Markdown table stays in the editor content flow and scrolls only with the surrounding page; it does not own a nested scroll container. Selected cells and whole selected tables use the same blue highlight as other selected blocks. |
| Browse database table views | Open a database page or an embedded database table | Full-page and embedded databases use one shared database component; its embed variation only adds the source link/dropdown. Tabs occupy the same transparent toolbar row as search/filter/source/new controls, with embedded source between Filter and New. The fixed 48-pixel toolbar uses 4-pixel vertical padding around a 40-pixel content band that centers every tab and control on one Y-axis, followed by an additional 6-pixel gap before the heading. Multiple table views retain independent nested filters, sorts, and exact visible columns. Views appear as 40-pixel independent pills: the active pill is filled and uses stronger text, while inactive pills have a neutral outline. Search, Filter, New, and the borderless Add View control retain their compact button sizes and remain centered; Add View is transparent until hover gives it a neutral fill. Pills do not overlap or join the table border. The white table heading uses only top and bottom rules. Compact, borderless bulk-selection checkboxes appear instantly on the block-handle axis outside the table surface, remain fixed during horizontal scrolling, and stay interactive inside embeds. A measured sibling overlay gives each checkbox a transparent hover target spanning the full height of its real header or row and the full gutter width to the table edge; the table contains no checkbox cells or anchors, so its normal-width scroll frame remains exactly constrained to the container. Tables use the editor content width and scroll oversized rows or columns inside a shared two-axis frame. Cell values wrap by default. Record names become plain inline editors with no focus border, background change, row-height shift, or text-baseline movement, and the caret starts at the end. Full-height header dividers appear only on header hover/focus to identify resizable boundaries; widths are browser-local preferences scoped to the workspace, database, and stable view ID rather than shared schema data. Table search expands immediately to a 224-pixel solid-white surface that fills the content band, so its inactive-pill-colored bottom rule exactly aligns with the pill bottoms. A separate preceding 44-pixel gradient runs from zero opacity through 50% white at 30% of its width to fully opaque white, making pill overlap fade earlier and more clearly. Bulk mode reuses that white band and fade, with every label sharing the toolbar's vertical center. The selection count becomes a blue-600 underlined `Clear all` action on hover/focus. Embedded bulk mode omits the database source selector. Escape closes and clears search and clears bulk selection, including both latent states when selection has hidden an open search. The frame has no outer border, top/bottom section separators, final-row bottom rule, or manual Refresh control; loading remains application-owned. |
| Filter database records | Activate the filter icon beside New on a database page or embed, build the rules, and select Apply | An anchored filter builder restricts conditions and values to the selected property type, offers searchable select-option values, and supports nested groups with isolated `and`/`or` logic. All edits remain local until Apply saves the complete tree to the active `.db.md` view for runtime evaluation. |
| Control database property visibility | Use a table column header context menu or an individual record page's properties menu | A column can be hidden and hidden columns can be restored only through table header actions; there is no toolbar visibility control. Table columns are shown or hidden only in the active view. Record-page properties use independent database-level record-page settings. Neither action deletes schema or frontmatter values. |
| Create a property | Activate a table or page property-create trigger, type a name, choose a type, and confirm | An anchored shared menu uses its search field as the exact name and type-ahead hint, displays types as an icon grid, supports arrow navigation, defaults to Text, moves focus to Date for a prefix such as `Dat`, confirms type on the first Enter, and creates on the second Enter. |
| Read and reuse code | Use a code block toolbar | The language is stored in the fence and selected through a searchable styled menu rather than a native browser selector, source can be copied, and Mermaid offers code/split/preview modes loaded only when needed. |
| Reuse content outside Rumi | Copy a text or block selection into a rich or plain destination | The browser clipboard carries every selected block in document order as portable semantic `text/html` plus readable `text/plain`, even when Rumi's explicit block highlight is represented internally by only one native selected node or an empty text cursor. Rich destinations such as Google Docs and Slack receive the complete selection with common formatting. Code uses semantic `<pre><code>` plus a neutral monospace/background presentation so rich editors that flatten the elements can retain a recoverable code boundary. Plain destinations retain line, paragraph, list, task, table, code, and embed boundaries. Rumi also carries the same complete selection as a private exact slice for lossless Rumi-to-Rumi paste. Cutting an explicit block selection exports and removes the same complete set. |
| Reuse workspace assets | Insert, paste, or drop an image/PDF | The client uploads bytes through the API; the runtime chooses a collision-safe `.assets/` path and emits `asset.changed`; Markdown stores only the relative path. |
| Manage Trash | Open Trash from the sidebar, then open, restore, or permanently delete an item | `/trash` uses the ordinary editor page title and content container without a title icon. Item kinds use a small unboxed icon beside the Page, Folder, Database, Upload, or File label rather than a leading item icon. Restore and Delete are ghost actions; destructive hover emphasis uses Rose 600. The address bar keeps the ordinary editor-page maximum width. |
| See linked resources at block level | Use standalone URLs, `![[file]]`, images, or `db` fences | The editor renders bookmark, file, image, and database-reference NodeViews while round-tripping the original Markdown syntax. |

## Migration Boundaries

- List items temporarily retain the proven editor's flat `indent` attribute model. This preserves
  per-item handles and the established drag behavior: vertical position chooses a block gap, while
  moving right chooses an allowed indent. Serialization still produces nested Markdown lists.
- Task items accept standard spaced GFM markers and legacy compact unchecked markers at every
  supported nesting depth. The editor writes the portable canonical source forms `- [ ]` and
  `- [x]`. Empty task source lines have no trailing space.
- Handles use one fixed editor-gutter X-axis even when list content is indented. The editor and the
  gutter to its left both activate the corresponding block handle.
- Heading collapse mode and Mermaid view mode are presentation state, not document data.
- The editor does not call filesystem or Electron APIs. Workspace assets go through runtime/API
  commands, so other clients can implement the same behavior.
- Automated platform-boundary coverage rejects Electron package imports, preload/IPC bridge APIs,
  legacy renderer imports, and Electron runtime dependencies from the active apps and packages.
- Bookmark metadata fetching is not required for a bookmark to work. The durable value is the URL.
- Mermaid uses the regular Phosphor Flow Arrow icon in the canonical block-type presentation shared
  by the handle context menu and slash menu.
- Database embeds remain references to database sources. Database relations are deliberately not
  implemented by this contract; Decision 019 remains the separate schema decision.
- A database embed may persist its selected stable view ID in the existing `db` fence. Saved view
  configuration still belongs only to the source database's `.db.md` file.

## Persistence Boundary

Every document-changing action updates ProseMirror first. Serialization is deferred from the
keystroke path and the client requests the current draft for autosave. Markdown/frontmatter remain
canonical, while selection, open menus, collapsed headings, and Mermaid display mode remain client
state. Inline replacement glyphs and selected emoji are real ProseMirror text, so the normal dirty,
serialization, versioned-save, revision, and reconciliation path persists them without a parallel
filesystem write.
